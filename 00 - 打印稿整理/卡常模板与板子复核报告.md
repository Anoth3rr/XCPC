该文件适合作为算法与卡常写法的参考，但不是可整体直接提交的独立代码库：多处依赖外部的 `mod / qpow / inv / mint / poly / cd / ull`、公共头文件和宏环境。本项目只吸收已补齐依赖、写明限制并通过差分的实现，不把参考代码原样视为“已验证模板”。

## 需要特别修正或保留限制的片段

1. `excrt` 只在注释中说明“无法整除就是无解”，代码没有检查 `(b-preB)%g`，矛盾同余组会被继续计算；赛时必须返回无解状态并检查最小公倍数乘法溢出。
2. `Barrett` 依赖外部 `ull`，并通过一组非常规运算符把 `mod` 当数使用；它只适合明确的无符号 64 位与正模数环境，不能替代通用自动取模类型。
3. 参考 HLPP 以最大流值为目标；gap 会把不能到达汇点的剩余盈余直接留在预流中，因此不能据其边残量直接断言“除源汇外流量守恒”。本项目 01C 重新实现了可查询、可 `reset()` 的完整边流接口。
4. 卡常 NTT 的 `root[23]=31`、`mod*mod` 等写法专用于 `998244353`，且依赖 `#define int long long` 避免中间量 32 位溢出；换模数、原根或整型环境时不能直接复用。
5. 浮点 MTT 没有对抗舍入误差的无条件保证，原片段也没有统一规范负系数。它不能作为 `convolution_mod_1000000007` 的 FFT-killer 解法；极限数据应使用三模 NTT + CRT。
6. 多项式后半部分大量依赖同一套 `mint/poly` 上下文，单独复制某一函数通常不能编译；本项目继续保留显式依赖，而不伪装成独立模板。

## 本轮落库

- `05/01C`：反向 BFS + highest-label + gap + 指针当前弧 + 周期全局重标号；容量仍默认使用宏展开后的 `int`，只有点边下标使用 `i32`。
- `06/08I`：Montgomery 模乘、radix-4 蝶形、根缓存、相同输入少做一次正变换、临界长度递归缩短变换。
- `06/08IA`：三次 08I + CRT 的精确任意模卷积；适配 `p <= 2^32-1`，并明确“三模乘积必须大于单项卷积绝对上界”。
- `08/01B`：两个实序列打包进一次复 FFT，大整数乘法由两次正变换加一次逆变换缩为一次正变换加一次逆变换。
- `01/linyue.hpp` 与《基础算法与 STL 速查》：增加 `_`、`tic/toc`、四套编译参数、对拍不变量、GDB 与卡常定位流程。

## 验证结果

- HLPP：与 Dinic 对拍 30000 组，覆盖自环、重边、反向边、零容量和最高约 `10^12` 的容量；逐边验证容量限制、除源汇外流量守恒、最大流等于最小割，并抽样验证 `reset()`。
- NTT：三个内部质数各随机差分 700 组，并对长度 `1..4096` 的 2 次幂验证 `intt(ntt(a))=a`。
- CRTNTT：对 8 个模数（含 `1` 与 `2^32-1`）随机差分 700 组；另在 `180000 × 170000` 卷积上抽查完整朴素系数。
- FFT-killer：按 Library Checker 官方生成器的 10 个种子构造 `n=m=524288` 的全部极限数据，逐项与官方三模 NTT 正解比较，10/10 完全一致。
- BigInt：124 组与 Python `int` 逐位比较，覆盖 0、正负号、前导零、1–300000 位随机数、全 9 和 09 交错极限输入。
- 所有上述测试另以 `_GLIBCXX_DEBUG + _GLIBCXX_DEBUG_PEDANTIC` 通过。当前精简 MinGW 未附带 `libasan/libubsan`，Sanitizer 应在 WSL/Linux 或完整 LLVM/MinGW 中复跑。

本机同一 GCC 13.2、`-O2 -DNDEBUG` 的单次参考数据：约 100.5 万边分层图的常规/极致 HLPP 为 `60/24 ms`；长度均为 524288 的 `998244353` 卷积为 `295/161 ms`；两个 50000 位整数相乘为 `128/13 ms`。时间只用于确认优化方向，不能替代目标评测机基准。
